## Общая информация
База данных выполнена на SQLite. В ней хранятся данные о пользователях, упражнениях, шаблонах тренировок, проведённых тренировках, истории веса и обратной связи. Схема обеспечивает целостность данных с помощью внешних ключей, проверочных ограничений (CHECK) и индексов для оптимизации производительности.

## Перечень таблиц

### 1. `users` – пользователи приложения
Хранит учётные записи, данные для расчёта стрика (серии тренировок), настройки профиля и цели.

| Поле | Тип данных | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | INTEGER | PRIMARY KEY | Уникальный идентификатор пользователя |
| `username` | TEXT | UNIQUE NOT NULL | Логин пользователя |
| `password_hash` | TEXT | NOT NULL | Хеш пароля |
| `name` | TEXT | | Имя пользователя (необязательно) |
| `created_date` | TEXT | NOT NULL DEFAULT (datetime('now')) | Дата и время регистрации аккаунта |
| `current_streak` | INTEGER | NOT NULL DEFAULT 0 | Текущая серия дней подряд с выполненными тренировками |
| `last_workout_date` | TEXT | | Дата последней выполненной тренировки (для расчёта стрика) |
| `avatar_url` | TEXT | DEFAULT '/static/images/default-avatar.jpg' | Путь к файлу изображения аватары пользователя |
| `weekly_goal` | INTEGER | DEFAULT 3 | Целевое количество тренировок в неделю |

---

### 2. `exercises` – справочник упражнений
Содержит названия и описания базовых упражнений, доступных для добавления в шаблоны и сессии тренировок.

| Поле | Тип данных | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | INTEGER | PRIMARY KEY | Уникальный идентификатор упражнения |
| `name` | TEXT | NOT NULL | Название упражнения (например, «Жим лежа») |
| `description` | TEXT | | Описание техники выполнения упражнения |
| `muscle_group` | TEXT | | Целевая группа мышц (например, «Грудь», «Ноги») |

---

### 3. `workout_templates` – шаблоны тренировок
Хранит структуру тренировок, созданных пользователями или администратором (для Библиотеки/Сообщества).

| Поле | Тип данных | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | INTEGER | PRIMARY KEY | Уникальный идентификатор шаблона |
| `user_id` | INTEGER | FOREIGN KEY (users.id) ON DELETE CASCADE | ID создателя шаблона (NULL для системных или привязанных к автору) |
| `name` | TEXT | NOT NULL | Название шаблона (например, «День ног») |
| `description` | TEXT | | Краткое описание или заметки к шаблону |
| `category` | TEXT | | Категория тренировки («Силовая», «Кардио», «Растяжка», «Йога») |
| `is_public` | INTEGER | NOT NULL DEFAULT 0 | Флаг публичности: `0` – приватный, `1` – опубликован в Сообществе |

---

### 4. `template_exercises` – упражнения в шаблонах
Связующая таблица (многие-ко-многим) между шаблонами и упражнениями с фиксацией планируемой нагрузки.

| Поле | Тип данных | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | INTEGER | PRIMARY KEY | Уникальный идентификатор записи |
| `template_id` | INTEGER | NOT NULL FOREIGN KEY (workout_templates.id) ON DELETE CASCADE | Ссылка на шаблон тренировки |
| `exercise_id` | INTEGER | NOT NULL FOREIGN KEY (exercises.id) ON DELETE CASCADE | Ссылка на упражнение из справочника |
| `sets` | INTEGER | | Планируемое количество подходов |
| `reps` | INTEGER | | Планируемое количество повторений |
| `weight` | REAL | | Планируемый рабочий вес (в кг) |
| `order_index` | INTEGER | NOT NULL | Порядковый номер упражнения внутри шаблона |

---

### 5. `workout_sessions` – календарь и сессии тренировок
Хранит запланированные, выполненные или пропущенные тренировки в календаре пользователя.

| Поле | Тип данных | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | INTEGER | PRIMARY KEY | Уникальный идентификатор сессии |
| `user_id` | INTEGER | NOT NULL FOREIGN KEY (users.id) ON DELETE CASCADE | Ссылка на владельца тренировки |
| `template_id` | INTEGER | FOREIGN KEY (workout_templates.id) ON DELETE SET NULL | Ссылка на исходный шаблон (сохраняется как NULL при его удалении) |
| `name` | TEXT | | Название конкретной тренировки |
| `date` | TEXT | NOT NULL | Дата и время проведения (в ISO формате) |
| `times` | INTEGER | | Длительность тренировки в минутах |
| `notes` | TEXT | | Общие заметки к тренировке |
| `status` | TEXT | NOT NULL CHECK (status IN ('planned', 'completed', 'missed')) | Текущий статус: запланирована, выполнена или пропущена |

---

### 6. `session_exercises` – выполненные упражнения в сессии (снапшоты)
Содержит фактические результаты по каждому упражнению, зафиксированные в момент выполнения тренировки.

| Поле | Тип данных | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | INTEGER | PRIMARY KEY | Уникальный идентификатор записи |
| `session_id` | INTEGER | NOT NULL FOREIGN KEY (workout_sessions.id) ON DELETE CASCADE | Ссылка на конкретную сессию тренировки |
| `exercise_id` | INTEGER | FOREIGN KEY (exercises.id) ON DELETE SET NULL | Ссылка на упражнение (NULL, если упражнение удалено из справочника) |
| `sets` | INTEGER | | Фактически выполненное количество подходов |
| `reps` | INTEGER | | Фактически выполненное количество повторений |
| `weight` | REAL | | Фактически использованный рабочий вес |
| `notes` | TEXT | | Заметки по выполнению конкретного упражнения |

---

### 7. `weight_log` – антропометрия (история веса)
Используется для фиксации изменений массы тела пользователя и построения графиков прогресса в профиле.

| Поле | Тип данных | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | INTEGER | PRIMARY KEY | Уникальный идентификатор записи |
| `user_id` | INTEGER | NOT NULL FOREIGN KEY (users.id) ON DELETE CASCADE | Ссылка на пользователя |
| `date` | TEXT | NOT NULL | Дата совершения замера веса |
| `weight` | REAL | NOT NULL | Значение массы тела (в кг) |

---

### 8. `feedback` – обратная связь от пользователей
Хранит отзывы, оценки и сообщения, отправленные пользователями через интерфейс обратной связи.

| Поле | Тип данных | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | Уникальный идентификатор записи |
| `user_id` | INTEGER | NOT NULL FOREIGN KEY (users.id) ON DELETE CASCADE | Ссылка на пользователя, оставившего отзыв |
| `rating` | INTEGER | NOT NULL CHECK (rating BETWEEN 1 AND 5) | Оценка приложения от 1 до 5 звезд |
| `subject` | TEXT | | Тема обращения |
| `message` | TEXT | NOT NULL | Текст сообщения/предложения |
| `created_at` | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | Дата и время автоматической фиксации отзыва |

---

## Оптимизация (Индексы)
Для ускорения работы поисковых запросов, построения графиков и быстрой отрисовки календаря используются следующие индексы:
* `idx_workout_sessions_user_date` — ускоряет выборку тренировок пользователя на определенный диапазон дат (Календарь/Дашборд).
* `idx_workout_sessions_status` — оптимизирует фильтрацию по статусам (например, для вывода только выполненных тренировок в Истории).
* `idx_session_exercises_session` — мгновенно подтягивает снапшоты выполненных упражнений для раскрывающихся карточек истории.
* `idx_template_exercises_template` — ускоряет сборку упражнений при открытии или клонировании шаблонов.
* `idx_weight_log_user_date` — оптимизирует выборку замеров массы тела для построения графиков прогресса в Личном кабинете.
